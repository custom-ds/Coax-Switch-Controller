# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project overview

A WiFi-enabled coax antenna switch controller for amateur radio stations (W0ZC). It lets two radios
each select one of six antennas (or disconnect) via relays, controlled from a front-panel rotary
knob + LCD or from a web UI/REST API served by the device itself. The repo contains three
largely-independent parts:

- `Firmware/` — the ESP32 (Arduino) firmware. This is the only part with "code" in the usual sense.
- `Coax Switch Controller/` — KiCad 8 project for the custom relay-driver PCB (schematic, PCB,
  Gerbers, BOM, fab outputs).
- `3d Case/` — FreeCAD enclosure design (body + lid) and STL exports for 3D printing.

There is no package manager, build script, or automated test suite in this repo — firmware is
compiled/flashed via the Arduino IDE, and the PCB/enclosure are edited in KiCad/FreeCAD.

## Firmware: building and flashing

There is no CLI build. Development happens in the Arduino IDE (optionally with VS Code as the
editor, per `Firmware/README.md`'s workflow: edit in VS Code, upload from Arduino IDE with both
pointed at the same `.ino`).

Setup required once per machine:
1. Install the `esp32` board package (by Espressif Systems) via Arduino IDE Boards Manager.
2. Install libraries via Library Manager: `AsyncTCP`, `ESPAsyncTCP`, `ESPAsyncWebSrv`,
   `Sparkfun Qwiic Twist Arduino Library`, `Sparkfun SerLCD Arduino Library` (see
   `Firmware/README.md` for pinned versions).
3. `ESPAsyncWebSrv`'s regex-based routes (used for all `/api/...` handlers) require a compiler
   flag that Arduino IDE doesn't expose in the UI. Create/update `platform.local.txt` (Windows:
   `%LOCALAPPDATA%\Arduino15\packages\espxxxx\hardware\espxxxx\{version}\platform.local.txt`) with:
   ```
   compiler.cpp.extra_flags=-DASYNCWEBSERVER_REGEX=1
   ```
   Restart the IDE after editing it. Without this, the API routes silently fail to match.
4. Select board "Sparkfun ESP32 Thing Plus C" and the correct COM port before uploading.

Secrets/config: `Firmware/config.h` is gitignored and must be created from
`Firmware/config.h.template`. It defines `ssid`, `password`, and static-IP settings
(`useStaticIP`, `local_IP`, `gateway`, `subnet`, DNS). Never commit `config.h`.

Local UI preview: `test_config.html` and `test_interface.html` at the repo root are gitignored,
hand-maintained static copies of the two web pages the firmware generates, used to iterate on
markup/CSS/JS in a browser without flashing hardware. When changing the UI, keep the HTML
generated by `getPageInterface()`/`getPageConfiguration()` (and these standalone files, if edited)
in sync — they're not templated from a shared source.

## Firmware architecture (`Firmware/Firmware.ino`)

Everything lives in one `.ino` file, organized (via comment-banner sections) into setup/loop,
helper functions, and "Views" (HTML/JS/CSS generation). There is no separate web framework —
pages are built by string concatenation with `%PLACEHOLDER%` substitution
(`getHeader()` + page body + `getFooter()`), and JS/CSS are served from `/main.js`/`/main.css`
as plain strings (`getJavascript()`, `getCSS()`), not static files.

**Antenna switching hardware model**: each radio has its own 3-bit demultiplexer selecting 1-of-6
relays (radio 1 on pins 12/27/33, radio 2 on pins 15/32/14), plus a shared enable pin (13) that's
pulled low while the select lines change and pulled high to latch. `connectAntenna(radio, antenna,
incrOnCollision)` is the single choke point for changing a radio's antenna: it enforces that the
two radios can never be connected to the same antenna simultaneously (antenna 0 = disconnected is
exempt), bumping the requested radio to the next/previous antenna on collision depending on
`incrOnCollision`, then drives the GPIOs and persists the new selection via `Preferences`
(`prefs`, namespace `"coax"`). `updateAntenna()` (knob-driven) and the `/api/.../connect/...` route
both funnel through this.

**Persistent state** (via ESP32 `Preferences`, namespace `"coax"`): last antenna per radio
(`radio1`/`radio2`), antenna display names (`ant0`..`ant6`, max 13 chars), LCD backlight
RGB+contrast, knob RGB, and a long-lived API key (`apikey`). `factoryReset()` (not currently wired
to any route/UI) resets all of this to defaults.

**API auth**: two keys are valid interchangeably — a `sessionAPIKey` regenerated in RAM on every
boot (handed to the web page's JS via `getJavascript()`'s `%APIKEY%` substitution) and the
persistent `apikey` from `Preferences` (visible on the LCD's config screen and dumped to Serial at
boot via `displayConfiguration()`). All `/api/{key}/...` routes validate via `checkAPIKey()`.
Routes use `ESPAsyncWebSrv` regex patterns (see the `server.on("^\\/api\\/...", ...)` calls) — the
regex build flag from setup step 3 above is required for these to match at all.

**Front panel UI** (SerLCD 16x2 + Qwiic Twist knob): `displayMode` toggles between normal operation
(1) and configuration (2). In normal mode, click toggles which radio (`radioSelected`) the knob's
twist affects; twisting calls `updateAntenna()`. A long press (`pressCount >= 5` in `loop()`)
enters config mode, which cycles read-only status screens (`configScreen`, 0..
`MAX_CONFIG_SCREENS`) via twisting; another click returns to normal mode. `updateLCD()` is the
single render function for both modes and is called after any state change.

## PCB and enclosure

`Coax Switch Controller/Coax Switch Controller.kicad_pro` is the KiCad 8 project (schematic +
PCB); `Gerber/` holds exported fab outputs and `Bill of Materials.csv` the BOM. `3d Case/` has the
FreeCAD source (`.FCStd`) for the enclosure body and lid plus sliced/exported `.stl`/`.bgcode`
files. These are edited directly in KiCad/FreeCAD — there's no scripted export or CI for them, so
regenerate Gerbers/STLs manually after design changes if downstream files need to stay current.
